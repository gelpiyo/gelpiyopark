# ゲルぴよ公園大作戦 ～ぴよ達の遊び場争奪戦～

Taica「ゲルぴよ」を題材にした **スマホWebブラウザ向けシミュレーションゲーム** のプレイアブル・プロトタイプです。
案件定義書（`ゲルぴよ公園大作戦_案件定義_川﨑_20260825.docx`）の 3章「コア機能・ゲームシステム」を、
実際に遊べる形で一通り実装しています。

- **内政（SimCity要素）**：空き地に遊具を建て、素材と「ごきげん度」を育てる
- **縄張り争い（信長の野望要素）**：ヘックスマップ19区画をライバル3勢力と奪い合う
- **バトル**：ヘックス戦場でのターン制オート進行（役割の三すくみ・地形・障害物あり）
- **コレクション**：スカウト（ガチャ）／装備／成長・進化
- **交渉（外交）**：おやつを贈って好感度を上げ、お約束・応援・区画譲渡

---

## うごかす

インストール・ビルド不要です。

### 1. 1ファイル版（いちばん手軽）

`dist/gelpiyo-park.html` をブラウザで開くだけ。約 200KB、外部通信ゼロ。
メール添付・USB・社内共有フォルダでそのまま配れます。

### 2. ローカルサーバ（PWA・オフライン動作の確認用）

Service Worker と manifest を効かせる場合は `http://` で配信してください。

```bash
python -m http.server 8123
```

ブラウザで `http://localhost:8123/` を開きます。
スマホで試す場合は同じLAN内から `http://<PCのIP>:8123/` へ。

### 3. 開発用ショートカット

`?dev=park` / `?dev=map` / `?dev=squad` / `?dev=gacha` を付けると、
資源と仲間を積んだ状態でその画面から始まります（動作確認用）。

## 操作

| 画面 | できること |
| --- | --- |
| 🏞 こうえん | 上部の2Dビューで公園のいまが見える（遊具タップで強化画面）。空き地をタップ→遊具を建設。「つぎの日へ」で1日進む |
| 🗺 なわばり | 区画をタップ→「せめこむ」でバトル、「こうしょう」でおやつ外交、自陣は「まもりをかためる」 |
| 🐣 なかま | 出撃メンバーの編成、さくせん変更、装備、かけら＋おやつで育成 |
| 🎁 スカウト | おさんぽ（1日1回無料）／1回／10連。結果画面で「なかまに する／にがす」を選択（10連はセルをタップして選り分け） |

勝利条件は **全19区画の制圧**、または **DAY 40 時点で最多区画**。全区画を失うと敗北です。

## ファイル構成

```
gelpiyopark/
├── index.html              画面の骨組み（全画面ぶん）
├── manifest.webmanifest    PWA（ホーム画面に追加）
├── sw.js                   Service Worker（オフライン動作）
├── css/style.css           スタイル（縦画面ベース）
├── assets/                 PWAアイコン（SVG／自動生成）
├── js/
│   ├── util.js             共通ユーティリティ・保存・乱数
│   ├── data.js             ★マスタデータ（施設/ぴよ/装備/勢力/地形/区画/定数）
│   ├── piyo.js             ゲルぴよ描画（SVG生成 & Canvas描画）
│   ├── hex.js              ヘックス座標計算
│   ├── state.js            ゲーム状態・経済・AI・日送り（DOM非依存）
│   ├── ui.js               HUD・タブ・モーダル・トースト
│   ├── parkscene.js        こうえんの2Dビュー（進捗の可視化）
│   ├── park.js             こうえん（内政）画面
│   ├── worldmap.js         なわばりマップ・進軍・交渉
│   ├── battle.js           バトル（シミュレーション＋再生）
│   ├── squad.js            なかま（編成・育成・装備）
│   ├── gacha.js            スカウト
│   └── main.js             起動・タイトル・メニュー・エンディング
├── dist/                   1ファイル版（tools/build.mjs で生成）
├── docs/仕様書.md          実装仕様と案件定義書との対応表
└── tools/
    ├── build.mjs           1ファイル版のビルド
    ├── sim.mjs             ロジックの自動テスト＆バランス確認
    ├── e2e.mjs             ブラウザ操作の通しテスト（CDP）
    └── shot.mjs            画面のスクリーンショット取得（CDP）
```

**バランス調整は `js/data.js` だけで完結します。** 施設の産出・コスト、ぴよのステータス、
勢力の強さ、地形、区画配置、ガチャ確率、ゲーム定数はすべてこのファイルに集約しています。

## 開発ツール

### バランス確認（ブラウザ不要）

```bash
node tools/sim.mjs 40
```

単体テスト → バトル勝率カーブ → 通しプレイ40回の統計、を順に出します。
`data.js` をいじったら、まずこれを回して壊れていないか確認するのがおすすめです。

### ブラウザ通しテスト

Chrome をデバッグポート付きで起動しておいてから実行します。

```bash
chrome --headless=new --remote-debugging-port=9222 about:blank
```

```bash
node tools/e2e.mjs
```

建設→日送り→進軍→バトル→交渉→育成→スカウト→セーブまで、実際にタップして例外が出ないか確認します。
同じ Chrome を使って `node tools/shot.mjs out.png "http://localhost:8123/?dev=map" 390 844` で
スクリーンショットも取れます（`docs/screens/` の画像はこれで取得したものです）。

### 1ファイル版のビルド

```bash
node tools/build.mjs
```

## 技術メモ

- **画像アセットを一切使っていません。** ゲルぴよはすべて `js/piyo.js` の
  SVG／Canvas 描画で、色相・装備・表情の組み合わせでバリエーションを作っています。
  そのため全体で約 200KB、初回ロードは実質待ち時間ゼロです（要件「ロード時間3秒以内」）。
- **ライブラリ・ビルド工程ゼロ。** 素の JavaScript（classic script）なので、
  `file://` で直接開いても動きます。
- **バトルは「先に決着まで計算 → イベントを再生」** の2段構え（`battle.js`）。
  決定論なので、同じシードなら必ず同じ結果になります。スキップ・倍速もこの構造ゆえに簡単です。
- **セーブは localStorage**（1データ約 3〜4KB）。20秒ごと＋離脱時に自動保存。
- **SVG の id は 1インスタンスごとに ユニーク**にしています。ぴよの「からだ」だけは
  `fill="url(#bd…)"` でグラデーションを参照しているため、キャッシュした SVG 文字列を
  そのまま使い回すと id が重複し、先に DOM から消えた方を参照していた個体の
  からだだけが消えます（とさか・ひれ・目は単色なので残る）。
  `js/piyo.js` の `stamp()` が取り出しのたびに id を振り直して防いでいます。
  `tools/e2e.mjs` に重複検出の回帰テストを入れてあります。

案件定義書の技術要件との差分と、本番実装への移行方針は `docs/仕様書.md` の
「案件定義書との対応」にまとめています。
