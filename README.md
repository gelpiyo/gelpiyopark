# ゲルぴよ公園大作戦 ～ぴよ達の遊び場争奪戦～

Taica「ゲルぴよ」を題材にした **スマホWebブラウザ向けシミュレーションゲーム** のプレイアブル・プロトタイプです。
案件定義書の 「コア機能・ゲームシステム」を実際に遊べる形で一通り実装しています。

- **内政（SimCity要素）**：空き地に遊具を建て、素材と「ごきげん度」を育てる
- **縄張り争い（信長の野望要素）**：ヘックスマップ19区画をライバル3勢力と奪い合う
- **バトル**：ヘックス戦場でのターン制オート進行（役割の三すくみ・地形・障害物あり）
- **コレクション**：スカウト（ガチャ）／装備／成長・進化
- **交渉（外交）**：おやつを贈って好感度を上げ、お約束・応援・区画譲渡

---

## うごかす

インストール・ビルド不要です。

### 1. 1ファイル版（いちばん手軽）

`dist/gelpiyo-park.html` をブラウザで開くだけ。約 420KB。
メール添付・USB・社内共有フォルダでそのまま配れます。ファイルを直接開いた（`file://`）ときは外部通信ゼロで、オンライン機能の項目も出ません。
1ファイル版にも窓口の接続先が入っています。オンライン機能（ランキング・アカウント引き継ぎ・セーブの控え）が使えるのは、窓口が許可している配信元（公開ページと同じ `https://gelpiyo.github.io`）に置いて開いたときだけです。
`dist/artifact.html`（Artifact 用）には接続先を入れず、オンライン機能はありません。

### 2. ローカルサーバ（PWA・オフライン動作の確認用）

Service Worker と manifest を効かせる場合は `http://` で配信してください。

```bash
node tools/serve.mjs 8123
```

ブラウザで `http://localhost:8123/` を開きます。
スマホで試す場合は `node tools/serve.mjs 8123 lan` で起動し、同じLAN内から `http://<PCのIP>:8123/` へ。

### 3. 開発用ショートカット

`?dev=park` / `?dev=map` / `?dev=squad` / `?dev=gacha` を付けると、
資源と仲間を積んだ状態でその画面から始まります（動作確認用）。

## 操作

| 画面 | できること |
| --- | --- |
| 🏞 こうえん | 上部の2Dビューで公園のいまが見える（遊具タップで強化画面）。空き地をタップ→遊具を建設。「つぎの日へ」で1日進む |
| 🗺 なわばり | 区画をタップ→「せめこむ」でバトル、「こうしょう」でおやつ外交、自陣は「まもりをかためる」 |
| 🐣 なかま | 出撃メンバーの編成、さくせん変更、装備、かけら＋おやつで育成 |
| 🎁 スカウト | おさんぽ（1日1回無料）／1回／10連。結果画面で「なかまに する／にがす」を選択（10連はセルをタップして選り分け） |

勝利条件は **全19区画の制圧**、または **タイムリミット最終日の時点で最多区画**（初期 DAY 10）。全区画を失うと敗北です。最終日を終えた時点で決着し、日付はそこで止まります。**タイムリミットでの決着と敗北はそこで終了**で、リザルトは「さいしょから」のみです（全区画制圧でのクリア後だけ続けて遊べます）。

ライバル3勢力（あかぴよ団・カラス組・野良ネコ軍団）のいずれかを **自分で全滅させると +10 日**、留守中に復活した相手を **倒し直すと +5 日** タイムリミットが延びます（`RULES.wipeBonus` / `wipeBonusAgain`）。ライバル同士の潰し合いで消えた場合は対象外です。

長時間の留守では全滅させた勢力が復活するため、**全区画制圧で勝っていても放置すると勝利が取り消されます**。

## 開発ツール

### バランス確認（ブラウザ不要）

```bash
node tools/sim.mjs 40
```

単体テスト → バトル勝率カーブ → 通しプレイ40回の統計、を順に出します。
`data.js` をいじったら、まずこれを回して壊れていないか確認するのがおすすめです。

### ブラウザ通しテスト

Chrome をデバッグポート付きで起動しておいてから実行します。

```bash
chrome --headless=new --remote-debugging-port=9222 about:blank
```

```bash
node tools/e2e.mjs
```

建設→日送り→進軍→バトル→交渉→育成→スカウト→セーブまで、実際にタップして例外が出ないか確認します。
同じ Chrome を使って `node tools/shot.mjs out.png "http://localhost:8123/?dev=map" 390 844` で
スクリーンショットも取れます（`docs/screens/` の画像はこれで取得したものです）。
`e2e.mjs` と `e2e-online.mjs` は、環境変数 `CDP_PORT` で Chrome のデバッグポートを変えられます（既定 9222）。

### オンライン機能のテスト（ランキング・アカウント引き継ぎ・セーブの控え）

どちらも **にせ窓口**（`tools/mock-ranking-server.mjs`）を自分で起動してつなぎます。本物の窓口へは通信しません。

```bash
node tools/online-test.mjs      # 通信・控えのロジック（ブラウザ不要）
node tools/e2e-online.mjs       # 画面の通しテスト（上と同じ Chrome と tools/serve.mjs が必要）
```

`e2e-online.mjs` は最初に接続先がにせ窓口であることを確かめ、違えば何もせず失敗で終わります。
終了時に、そのオリジンの localStorage（セーブ・成績・アカウント）を実行前の状態へ戻します。

窓口の接続先は `godot/data/ranking.json` が唯一の元です。変えたときは次を実行します。

```bash
node tools/export-net.mjs           # js/netconfig.js を書き直す
node tools/export-net.mjs --check   # 書かずに、ずれていないかだけ確認（ずれていれば終了コード 1）
```

オンライン機能は、ページが `http(s)://` で開かれ、かつ自動の検査（headless Chrome など）でないときだけ窓口へつなぎます。
`file://` で開いたとき・Artifact 用（`dist/artifact.html`）・自動の検査では、メニューとタイトルの「アカウント・ひきつぎ」は出ず、窓口へ一切通信しません。

### 1ファイル版のビルド

```bash
node tools/build.mjs
```

## 技術メモ

- **画像アセットを一切使っていません。** ゲルぴよはすべて `js/piyo.js` の
  SVG／Canvas 描画で、色相・装備・表情の組み合わせでバリエーションを作っています。
  全体で約 290KB、初回ロードは実質待ち時間ゼロです（要件「ロード時間3秒以内」）。
- **2Dの ゲルぴよも 実機モデル準拠。** `tools/outline.mjs` が 3Dモデルの正面投影から
  シルエット輪郭・目・くちばしの位置を抽出して `js/piyo.js` の SHAPE に埋め込み、
  SVG／Canvas の描画アルゴリズムはこのデータから形を起こします（表情・装備・色相はそのまま）。
  モデルが更新されたら `node tools/mesh.mjs` → `node tools/outline.mjs` の順で追従できます。
- **実機の3Dモデル（SolidWorks製 GLTF）を搭載。** `tools/mesh.mjs` が
  26,500頂点 → 2,136頂点（50KB）に軽量化して埋め込み、`js/piyo.js` の
  自前WebGLレンダラ（ライブラリなし・約200行）がタイトル・ぴよ詳細・スカウト画面で
  表示します。からだの色は2Dと同じ色相システムで着色。WebGL が使えない環境では
  自動的に SVG 版へフォールバックします。
- **ライブラリ・ビルド工程ゼロ。** 素の JavaScript（classic script）なので、
  `file://` で直接開いても動きます。
- **バトルは「先に決着まで計算 → イベントを再生」** の2段構え（`battle.js`）。
  決定論なので、同じシードなら必ず同じ結果になります。スキップ・倍速もこの構造ゆえに簡単です。
- **セーブは localStorage**（1データ約 3〜4KB）。20秒ごと＋離脱時に自動保存。
- **SVG の id は 1インスタンスごとに ユニーク**にしています。ぴよの「からだ」だけは
  `fill="url(#bd…)"` でグラデーションを参照しているため、キャッシュした SVG 文字列を
  そのまま使い回すと id が重複し、先に DOM から消えた方を参照していた個体の
  からだだけが消えます（とさか・ひれ・目は単色なので残る）。
  `js/piyo.js` の `stamp()` が取り出しのたびに id を振り直して防いでいます。
  `tools/e2e.mjs` に重複検出の回帰テストを入れてあります。

案件定義書の技術要件との差分と、本番実装への移行方針は `docs/仕様書.md` の
「案件定義書との対応」にまとめています。

## 外部コード・出典

外部ライブラリ（npm・CDN・Webフォント）は使っていません。ツールの import も Node 標準モジュールのみです。
他者の公開コード・解説をもとにした箇所は次の2つで、ソースにも出典を記載しています。

| 箇所 | もとにしたもの | ライセンス |
| --- | --- | --- |
| `js/util.js` の `makeRng`（乱数） | Mulberry32 — Tommy Ettinger（[gist](https://gist.github.com/tommyettinger/46a874533244883189143505d203312c)）／JavaScript 版 bryc "[PRNGs](https://github.com/bryc/code/blob/master/jshash/PRNGs.md)" | CC0 1.0／パブリックドメイン |
| `js/hex.js`（ヘックス座標の計算） | Amit Patel "[Hexagonal Grids](https://www.redblobgames.com/grids/hexagons/)", Red Blob Games | 数式・擬似コードを参考に独自実装 |

ゲルぴよの3D形状（`js/piyodata.js` ほか）は、Taica 提供の `gelpyto_3D_mod.gltf` から変換したデータです。
