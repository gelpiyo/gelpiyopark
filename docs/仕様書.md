### ごきげん度（内政の中心指標）

```
ごきげん度 = 34
           + 50 × (1 − e^(−遊具ごきげん合計 / 48))   ← 逓減。同じ物ばかり建てても伸びない
           + min(区画数, 3) × 2.2
           − max(0, 区画数 − 3) × 1.9                ← 広げすぎると目が届かない
           − max(0, なかま数 − 定員) × 4.2           ← 混雑ペナルティ
           + 装備ボーナス + イベント補正（日ごとに減衰）
```

- **産出倍率** = 0.5 + ごきげん度 / 100（0.5〜1.5倍）
- **戦闘攻撃倍率** = 0.72 + ごきげん度 / 200（0.72〜1.22倍）
- **25未満 → だだっこストライキ**：産出がさらに 0.45倍。PWA通知で再訪を促す

領土を広げるほどごきげん度が下がるため、**「攻める」と「整える」を往復させる**構造になっています。
案件定義書 3.1 の「ごきげん斜め（だだっこストライキ）」を、単なる警告ではなく
内政と侵攻のトレードオフとして機能させています。

### 放置生産

`lastSeen` のタイムスタンプ差から、再訪時に経過時間ぶんを付与します（1時間＝1日の42%、最大8時間ぶん）。
ブラウザを閉じていても素材が貯まります（案件定義書 3.1）。

さらに **8時間を超えた分は「8時間＝1日」として日付が自動で進みます**
（進む日数 ＝ (経過時間 − 8時間) ÷ 8時間 の切り捨て。例：30時間留守 → +2日）。
自動で進んだ日も通常どおり 日次収入・イベント・げんき回復・ライバルAIの拡張 が起きます。
防衛バトルは挟めないためライバルのランダムな襲撃は起きませんが、かわりに
**進んだ1日ごとに「まもり」が最も低い自区画を1つ、その時点で最も弱い勢力
（区画数最少。同数なら勢力係数の低い方）にのっとられます**（ごきげん度も少し低下）。
全滅した勢力（区画数 0）も候補に含まれ、区画数最少として最優先で選ばれるため、
長期の留守は **滅ぼしたライバルの敗者復活** につながります。
**決着した日でものっとりは起きます。** 全区画制圧で勝った直後に1マス取り返されると
**勝利判定そのものが取り消され**（`st.ended = null`）、続きから再開になります
（`applyOffline` が `revoked` を返し、「おかえりなさい」画面に「😱 しょうりが くつがえった！」を表示）。
留守前に守りを固める動機づけであり、「勝ったまま放置すれば安泰」を防ぐ仕様です。
取り消すのは **タイムリミット内の全区画制圧による勝利だけ**で、
時間切れ（DAY 超過）の決着は日付を戻せないためそのまま残します。
`restore()` にも同じ判定を入れてあり、旧バージョンで矛盾したまま保存されたセーブも続きに戻します。
ただし**最後の1マス（ホーム）だけは奪われません**（留守中の全滅はなし）。
のっとられた区画は再開時の「おかえりなさい」画面と こうえん日記に表示されます。
決着（DAY 40超過など）に達した場合は再開時にリザルトを表示します。

### 区画の防御力

```
自陣  : 基礎 + 地形 + とりでLv×2 + min(4, 支配日数/5)
敵陣  : (基礎 + 地形) × 勢力係数 × (1 + 経過日数 × 0.024)
```

プレイヤーが区画を取ると、**隣接するライバル区画の防御が +1**（警戒）。
攻めるほど周りが硬くなるので、一方的な雪だるま式にならないようにしています。

### 勢力の全滅ボーナス（タイムリミット延長）

ライバル勢力（`RIVALS` = red / crow / cat）を **プレイヤーが全滅させるたびにタイムリミットがのびます**。
初回は `RULES.wipeBonus`（= 10）日、**復活した相手を倒し直した2回目以降は
`RULES.wipeBonusAgain`（= 5）日**です（勢力ごとに `st.wipedOnce[fac]` で判定）。実効リミットは `state.dayLimitNow()`
（`RULES.dayLimit` + `st.dayBonus`）で、こうえんの「のこり◯日」・メニュー・リザルト・
決着判定（`checkEnd`）はすべてこの値を見ます。

判定は `state.checkWipe(byPlayer)` に集約し、所有が変わりうる場所すべてから呼びます。
**ボーナスが出るのは `byPlayer = true` のときだけ**です。

| 呼び出し元 | byPlayer | ボーナス |
| --- | --- | --- |
| せめこみ勝利（`worldmap.doAttack`） | true | ○ |
| 外交の割譲「区画をゆずってもらう」 | true | ○ |
| `nextDay` のライバルAI（AI同士の潰し合い） | false | × |
| るす中ののっとり（`offlineSteal`） | false | × |

勢力ごとに `st.wiped[fac]` フラグを持ち、**区画が戻った（＝復活した）ら下ろす**ので、
復活した勢力を自分で倒し直せば、もう一度 +10 日もらえます。二重取りはしません
（同じ全滅状態のまま何度呼んでも 1 回だけ）。AI に消された勢力はフラグだけ立つため、
そのままでは後からボーナス化しません（復活 → 自分で全滅、なら対象）。

セーブ互換：`dayBonus` / `wiped` は `restore()` で初期値を補完するため、旧セーブも壊れません。

### ライバルAI

1日1回（DAY 10以降は2回）行動します。

1. `aggr` 判定に外れたら自陣の防御を固める
2. 隣接する非自陣区画を重み付き抽選（中立を好み、防御が低いほど狙われやすい）
3. 対象がプレイヤー区画なら **防衛戦（プレイヤーが操作するバトル）** を発生させる
4. それ以外は確率判定で即時決着

お約束（平和条約）が有効な間はプレイヤーを攻めません。

## 5. バトル

案件定義書 3.2 の「ヘックス状の公園マップでターン制・オート進行」を実装。

**5列 × 9行のヘックス戦場**（縦画面に合わせた縦長）。プレイヤーは下2行、敵は上2行から開始。

### 処理の流れ

`battle.js` は **①先に決着まで全計算 →②イベント列をアニメで再生** の2段構えです。
決定論なので同じシードなら必ず同じ結果になり、スキップ／倍速（×1/×2/×4）が破綻しません。

```
simulate(cfg) → { events[], winner, survivors[], downed[] }
                  ↓
play(events)   → move / attack / heal / debuff / down / turn / end を順に描画
```

1ターンの流れ：素早さ順に行動 → 支援役は回復を優先 → 射程内なら攻撃、届かなければ
ダイクストラで最短経路を移動（障害物・味方を回避）→ 移動後に射程に入れば攻撃。
最大34ターン、決着しなければ残HP割合で判定。

### 役割と三すくみ

| 役割 | HP | 攻 | 防 | 射程 | 移動 | 速 | 特徴 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| そっこう 速 | 56 | 14 | 4 | 1 | 3 | 12 | えんきょりに ×1.5 |
| えんきょり 遠 | 44 | 15 | 3 | 3 | 2 | 10 | ぼうぎょに ×1.5 |
| ぼうぎょ 盾 | 88 | 9 | 10 | 1 | 2 | 7 | そっこうに ×1.5 |
| さくせん 策 | 48 | 8 | 5 | 2 | 2 | 11 | 味方を回復 |
| たいしょう 将 | 74 | 16 | 7 | 1 | 2 | 9 | 味方全体 攻撃+6% |
| おじゃま 妨 | 52 | 10 | 5 | 2 | 3 | 13 | 相手の攻撃 −18%（3ターン） |

弱点側は ×0.7。「そっこう ▶ えんきょり ▶ ぼうぎょ ▶ そっこう」の三すくみです。

### ダメージ計算

```
攻撃力 = 攻 × 相性 × オーラ × デバフ × ごきげん補正 × 作戦補正
       × (遠距離かつ遮蔽ありなら 1 − 遮蔽率)
ダメージ = max(1, (攻撃力 − 防御 × 0.55) × rand(0.9〜1.1))
かいしん = 4% + (速さ差 × 1.2%)（2〜28%）→ ×1.55
```

### 実機3Dモデルの表示

Taica 実機の 3Dモデル（`gelpyto_3D_mod.gltf`／SolidWorks 出力）をゲームに埋め込み、
**タイトル画面・ぴよ詳細モーダル・スカウト画面** で本物の形状を表示します。

- 変換：`node tools/mesh.mjs <gltfのパス>` が頂点クラスタリングで
  26,500頂点 → 2,136頂点／4,257三角形（50KB）に軽量化し、int16量子化＋base64 で
  `js/piyodata.js` に埋め込みます（からだ／目／くちばし／ほっぺの4パーツ構成を維持）
- 描画：`js/piyo.js` 内の自前 WebGL レンダラ（外部ライブラリなし）。
  ランバート＋強めのスペキュラ＋リムライトで**ゲル素材のツヤ**を表現
- 色：からだは 2D と同じ色相システム（hue/sat/lit）で着色されるため、
  種族・進化ごとの色違いが 3D にもそのまま反映されます
- 操作：自動回転＋ドラッグで回せる（詳細モーダル）。
  WebGL 不可の環境・カラス／ネコ勢力は自動的に 2D 表示へフォールバック
- **装備品も 3D 表示に反映**：装備10種を手続き生成の3Dパーツ（箱・円柱・円錐の
  組み合わせ、`ACC3D`）としてモデルに装着。2Dと同じ配色で、回転にも追従します。
  ぴよ詳細で装備を付け替えると 3D ビューも即座に切り替わります
- 一覧・バトル・公園ビューなど多数表示の場面は軽量な 2D 描画のまま。ただし
  **2D の形状も 3Dモデル由来**：`tools/outline.mjs` が正面投影をラスタライズ →
  輪郭トレース → 単純化して、シルエット（とさか・はね・あし込み 62点）と
  目・くちばし・くちラインの実測位置を `js/piyo.js` に埋め込み、
  SVG と Canvas はそこから描画します。表情差分・装備・色相システムは 2D 側で維持
  （カラス組・野良ネコ軍団は別キャラクターのため従来デザインを継続）

## 7. スカウト（ガチャ）

| | 排出率 | 被り時のかけら |
| --- | --- | --- |
| SR | 4% | 40 |
| R | 26% | 12 |
| N | 70% | 4 |

- おさんぽスカウト：1日1回無料
- 1回：🎴5
- 10連：🎴45（最後の1枠は R 以上確定）

結果画面では **「なかまに する」「にがす」の2択** で確定します。
にがすとレアリティに応じたかけら（N🧩4／R🧩12／SR🧩40）になります。
10連では結果セルをタップして「にがす子」を1体ずつ選り分けられ、
「なかまに する」で残りが仲間になります。✕や背景タップで閉じた場合は
誤操作で消えないよう「なかまに する」扱いです。
同種3体以上、またはなかま上限に達している子は「なかまに する」を選んでも
自動でかけらに変換されます（NEW判定は仲間にした時点で記録）。
抽選結果は確定前にセーブへ保存されるため、**選ぶ前にブラウザを閉じても
引いた子は消えません**（次回「つづきから」で結果モーダルを復元。にがすマークも引き継ぎ）。

## 8. 交渉（おやつ外交）

案件定義書 3.2 の「おやつ交渉」を、好感度を軸にした外交システムとして実装。

**贈り物**（好感度は ±2 のブレあり）

| 贈り物 | コスト | 好感度 |
| --- | --- | --- |
| 高級ジュース 🥤 | 🥤18 | 約 +9 |
| 高級おやつ 🍪 | 🍪12 | 約 +14 |
| レアメンコ 🎴 | 🎴3 | 約 +26 |

**おねがいごと**（好感度を消費）

| おねがい | 必要 | 効果 |
| --- | --- | --- |
| お約束（平和条約） 🤙 | 50 | 4日間おたがい攻めない（−8） |
| おうえんを たのむ 📣 | 70 | 次の対戦に味方が1体増援（−14） |
| 区画を ゆずって もらう 🏳 | 88 | 最も防御の低い区画を譲渡（42にリセット） |

好感度は何もしないと毎日 −1 ずつ下がり、その勢力から区画を奪うと −12 されます。

| ゲームエンジン Phaser / PixiJS | 素の Canvas 2D ＋ SVG | この規模ではエンジンのコスト（Phaser 単体で1MB超）が要件「ロード3秒以内」と釣り合わない。全体200KBに収まり、ビルド工程も不要になった。**パーティクル演出を厚くする段階で PixiJS へ差し替え可能**（描画層は `piyo.js` と各画面の `draw` に閉じている） |

## 10.5 既知の落とし穴（実装メモ）

### ぴよの「からだ」だけが消える — SVG id の重複

ぴよの本体は `fill="url(#bd…)"` でグラデーションを参照しており、
**`url(#…)` はドキュメント全体から id を探す**仕様です。
一方 とさか・ひれ・あし・目・くちばし はすべて単色塗りです。

`piyo.js` は同じ見た目の SVG 文字列をキャッシュして使い回すため、対策をしないと
同じ id を持つ SVG が画面に複数並びます。この状態で、先に DOM から消えた方
（一覧の再描画、モーダルを閉じる、タブ切り替えなど）を参照していた個体は
参照先を失い、**からだだけが描かれなくなります**。
未装備のぴよで起きやすいのは、同種・未装備の個体がまったく同じキャッシュキーを共有し、
id が衝突しやすいためです（装備を付けるとキーが変わり別 id になるので、
一見「装備すると直る」ように見えます）。

**対策**：キャッシュには id を目印文字列 `__GID__` にしたひな形を保存し、
`stamp()` が取り出しのたびに一意な id へ差し替えます（`js/piyo.js`）。
`tools/e2e.mjs` に「SVG id 重複なし」「からだの塗り参照ぎれなし」の回帰テストを追加済みです。

> Chrome では参照が解決し直されて表示されることもありますが、
> **iOS Safari は再解決しない**ため、対応環境を考えると必須の対策です。

## 11. 本番への道筋

プロトタイプの構造は、そのまま本番の下敷きになるよう分けてあります。

```
                        いま                      本番
  マスタデータ    js/data.js              → 管理画面 + バイナリ配信
  ゲームロジック  js/state.js（DOM非依存）  → そのままサーバへ移植可能（権威サーバ化）
  バトル          js/battle.js（決定論）    → サーバで simulate、クライアントは play のみ
  描画            js/piyo.js + 各画面       → PixiJS 差し替え or 現状維持
  保存            localStorage             → REST + サーバDB（localStorage はオフライン用に併用）
```

**`state.js` と `battle.js` が DOM に一切触らない** のは意図的です。
`tools/sim.mjs` はこの2つだけを Node 上で読み込んでバランス検証しており、
同じコードをそのままサーバ側の権威ロジックに転用できます。
バトルが決定論（シード固定）なのも、**サーバ計算＋クライアント再生**へ移行するための布石です。
